## 🔨 Featured Engineering Work

### 🧊 Object Generator

An open-source Python project for generating artist-editable 3D assets, currently integrated with Blender through a deliberately thin adapter layer.

The project separates its **host-independent generation core** from Blender-specific functionality so the underlying system can evolve beyond a single 3D application.

**Engineering focus:**
- Python architecture and reusable domain models
- Host-independent geometry, proportions, rigging, and validation
- Thin application adapter design
- Automated tests and add-on packaging
- Open-source development and GPL licensing

➡️ [Explore Object Generator](https://github.com/jhodges0845/blender-object-generator)

### 🎮 GameBoost

A C#/.NET game framework project built around abstraction, portability, and reusable game systems.

GameBoost has been an environment for exploring how rendering, textures, screens, cameras, physics, and other game-engine concerns can be separated behind clean interfaces instead of tightly coupled to a specific implementation.

**Engineering focus:**
- C# and .NET
- Interface-driven architecture
- Rendering abstractions
- 2D game systems and physics
- Unit testing and CI
- Cross-platform design

➡️ [Explore GameBoost](https://github.com/jhodges0845/GameBoost)

## 🧭 How I Approach Engineering

I tend to work at the intersection of **software and systems thinking**.

That often means:

- Understanding an existing system before replacing it
- Separating business logic from infrastructure and vendor-specific dependencies
- Automating repetitive engineering and operational work
- Building reusable components instead of solving the same problem repeatedly
- Improving delivery through Git, CI/CD, testing, validation, and documentation
- Designing systems so today's implementation does not unnecessarily limit tomorrow's options

I am particularly interested in problems where architecture can turn a one-off solution into a platform.
